# Token-denominated contract extension

The current deployment accounts for requests. The local extension adds a governance-registered metered issuer whose policies use denomination version 2. It uses integer provider tokens. The existing request and token methods reject the other denomination. Metered issuers have their own lifetime caps so one cap never mixes units.

`reserve_tokens` takes the same ownership epoch, sequence, commitment, and block deadline as a request reservation, plus an integer maximum. `settle_tokens` consumes actual usage at or below that maximum and returns unused units. An actual value of zero releases the full reservation. Duplicate settlement returns the existing evidence within the bounded settlement window. An ownership transfer invalidates stale authorizations while preserving open reservations. The settler remains responsible for verifying reported usage. An expired admission deadline prevents late reservation and leaves an applied reservation eligible for settlement.

The extension appends three new storage prefixes and keeps the root state and all existing stored value layouts. No state rewrite is intended. Before upgrade approval, test a real v1 WASM deployment followed by a sandbox v2 upgrade and verify pre-upgrade policies, passes, open reservations, settlement evidence, enumeration, and callback behavior. Verify storage bounds and reproducible WASM hash. Pause issuer activity and drain metered work before any rollback because v1 cannot interpret version 2 accounting. Production deployment requires separate authorization.
