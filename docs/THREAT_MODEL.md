# Contract threat model

- **Stale holder or replay.** The reserve receipt checks issuer authorizer, owner, epoch, sequence and block-height window before any debit. Returning the token to its former owner advances the epoch. Retry settlement returns a bounded evidence result and never repeats a credit effect.
- **Relayer compromise.** The restricted authorizer can impersonate a current holder and commit credits under its issuer. Use a scoped function-call key and monitor reserve events. An issuer or governance pause stops future reserves. A holder-signed permit remains a future design.
- **Settlement compromise.** The settler can choose disposition for open reservations. It cannot mint or apply a disposition twice. Independent provider evidence and operator reconciliation are off-chain responsibilities.
- **Asynchronous receiver.** The resolver binds a private callback to its recorded token and transfer ID. Failed or malformed receiver results request return. Current ownership decides rollback. Every pending entry holds new compute authorization. Failed resolution leaves the hold in place until reviewed repair. Existing work can still settle.
- **Storage and gas exhaustion.** Mutations require issuer prepayment for storage capacity. Transfers preserve standard onward ownership behavior. Callback entries consume a finite issuer-funded pool and use bounded data and dedicated resolver gas. Exhaustion can reject additional transfer-calls.
- **Governance and upgrades.** Governance registers issuers and pauses mint/reserve globally. The contract account's upgrade keys can replace code and are separately trusted. No public method reassigns an owner's balance. Production custody and any repair migration require independent review.
- **Privacy.** Public events contain account IDs, credit counters and opaque request commitments. Prompts, outputs and provider credentials belong outside the contract. No provider execution or billing evidence is proven by contract settlement.
